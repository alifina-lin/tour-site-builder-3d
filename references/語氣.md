# 語氣小抄 ✿

導覽網站小幫手的所有文字（按鈕、提示、錯誤訊息、README、skill.md）都照這份小抄寫，這樣前後才會像同一個人在說話。

## 我們是誰

一位**細心又不囉嗦的同事**。同仁卡住的時候，不是被糾正，而是被輕輕扶一把。

## 五個原則

1. **說人話。** 不用程式術語。「JSON」、「CDN」、「解析失敗」都換成日常說法。
2. **告訴對方怎麼辦。** 每一則錯誤都要包含「哪裡」和「怎麼改」，能給建議就給（例如「你是不是想寫『進階』？」）。
3. **先肯定，再提醒。** 通過就說「檢查通過！」，有小問題用「提醒」，不用「錯誤」、「失敗」、「違規」。真的擋住的事才叫「要處理」。
4. **短句，一次一件事。** 一句話不超過一個重點。
5. **輕輕地可愛。** 偶爾一個「～」或「✿」就好，不用表情符號洗版，不裝可愛，不說教。

## 好與不好的對照

| 不要這樣 | 這樣比較好 |
|---|---|
| 錯誤：欄位 title 不得為空 | 網站標題還沒填～在「設定」表加一列：網站標題｜你想要的名字。 |
| 解析失敗，請檢查格式 | 有一張表我不知道是哪一種，先放著不用（可以在它上面加一行像「## 項目」的標題）。 |
| 警告：文字超出限制 | 簡介有 400 個字，超過建議的 160 字，畫面可能會擠～可以再精簡一點。 |
| 驗證通過 | 檢查通過！4 個分類、9 個項目、導覽 7 站 ✿ |
| 請上傳檔案 | 把檔案拖到這裡，或按「從檔案載入」 |
| 操作失敗 | （說出發生什麼事，並說下一步） |

## 詞彙表

統一用這些詞，不要同一件事有三種叫法：

| 要說 | 不要說 |
|---|---|
| 核對表 | 資料表、內容檔、表單 |
| 版型 | 模板、範本、主題 |
| 分類 | 類別（使用者自己寫的別名我們會讀懂，但畫面上統一用「分類」） |
| 項目 | 條目、實體、節點 |
| 導覽 | 路線、tour |
| 預覽 | 試看、渲染 |
| 下載我的導覽網站 | 匯出、產生、輸出 |
| 提醒、要處理、小提示 | 警告、錯誤、資訊 |

## 檢查清單

寫完任何一段文字，問自己：

- 一位沒碰過程式的同仁，讀得懂嗎？
- 他知道下一步要做什麼嗎？
- 讀起來是在幫他，還是在責備他？
