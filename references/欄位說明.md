# 六張表欄位說明

欄位名稱請一字不改。標「必填」的欄位空白會被擋下；其他欄位空白也成立（畫面會自動略過）。

## 1_全站設定（只有一列）

| 欄位 | 必填 | 說明 |
|---|---|---|
| 標題 | ✓ | ≤ 15 字 |
| 副標 | | 一句說明 |
| 開場標語 | ✓ | ≤ 25 字，全景要讓人記住的那句話 |
| 導言 | ✓ | 60–100 字，開場頁說明 |
| 記得的事1～3 | | 每件 ≤ 20 字，不上畫面，給製作者對焦 |
| 收束結語 | ✓ | 60–100 字 |
| 聯絡方式 | | 看完要讀者做什麼 |
| 隱喻世界 | | 例：數位校園小鎮 |
| 品牌色 | | #RRGGBB，類別色從它延伸 |
| 範本 | | 場景：「小島」（空白、`islands`、`town` 都是它）、「大樓」（`tower`）或「市集」（`market`）；舊名「六角群島」「科技大樓」也還能用。不認得的值一律用小島。小幫手頁面右上也可以直接切換 |

## 2_類別表（4–6 列）

代號✓、名稱✓、識別色✓（#RRGGBB，柔和低彩度）、一句話定位、隱喻造型（決定建築外型，見 SKILL.md 對應規則）、地面（紅磚／草地／木地板，選填）、邊界（綠籬／木柵欄／原樣／混搭，選填）。一個類別就是一座島（大樓是一層樓、市集是一區帳篷）；沒填地面與邊界時，系統會自動搭配出彼此不同的島。一座島最多放 6 個項目（超過會被提醒拆成兩個分類）；4 個起建築會自動高低錯落，全景只顯示分類名。

## 3_步驟表（導覽主線，6–12 列，最關鍵）

順序✓、類別代號✓（對到類別表）、實體代號✓（對到實體表）、宣告標題✓（≤ 12 字）、宣告副句（≤ 25 字，從使用者角度寫）、數據1～3（各有 數值／單位／標籤／年份／來源 五欄，來源填來源代號）、案例類型、案例內容（40–60 字，真人真事，可去識別化）、說明文字✓（80–150 字）、圖片檔名（16:10，中文檔名方便換圖）。

## 4_實體表（點開的細節）

代號✓、名稱✓、類別代號✓、一句話亮點✓（≤ 28 字，具體有記憶點）、數據1～2（五欄）、簡介✓（50–90 字）、沿革（≤ 60 字）、怎麼使用／申請、資源1～3（名稱＋連結）、聯絡窗口（單位或信箱，不放個人資料）、圖片檔名。不一定每個實體都出現在導覽裡。

## 5_動態元素表（8–12 列）

名稱✓、象徵什麼✓、出現位置（實體代號、類別代號或名稱）、地標文字。每一項都要說得出它和內容的關係。

## 6_來源表

來源代號✓、來源名稱✓、年份✓、連結、算法說明（例：日均進出＝全年上車＋下車 ÷ 365）、提供人。每個數據都要對到一列來源。

## 準備原則

- 先填步驟表，再補實體表：先想要帶讀者走哪條路，再決定哪些細節值得點開。
- 每個欄位都守字數上限，這套設計靠節奏。
- 數據五件套缺一就先不放，畫面會自動隱藏那一格。
- 案例要真人真事：不寫「使用者可以快速登入」，要寫「新生入學第一天就能登入所有系統」。
- 區分誰提供、誰審核：數據與案例由業務承辦提供，說明文字由整理者統一轉譯成讀者語言。
